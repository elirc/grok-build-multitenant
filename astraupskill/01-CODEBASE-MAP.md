# Map the request and its trust boundaries

Start with [the application factory](../backend/src/app.ts), which configures Express, JSON limits, CORS, request IDs, authentication, and routes. [The process entry point](../backend/src/index.ts) reads configuration, binds to loopback, and closes HTTP and Prisma resources on shutdown. Separating these files lets tests instantiate the real application without accidentally starting an unmanaged server.

[Authentication](../backend/src/middleware/auth.ts) verifies an HS256 token with a subject, issuer, audience, and expiry. Login compares a bounded password with a stored bcrypt hash. The token identifies a user; it does not carry an authoritative organization role. [Tenant middleware](../backend/src/middleware/tenantContext.ts) validates the selected `x-org-id`, reads the matching membership from PostgreSQL, and attaches verified user, organization, and role context. There is no fallback demo tenant.

[Routes](../backend/src/routes/projectRoutes.ts) adapt HTTP paths to operations. [Controllers](../backend/src/controllers/projectController.ts) handle the project list/create response shape, while [services](../backend/src/services/projectService.ts) apply role policy and [input schemas](../backend/src/lib/validation.ts). [The repository](../backend/src/repositories/projectRepository.ts) performs organization-scoped queries and transactions using [one Prisma client](../backend/src/lib/prisma.ts). The [database schema](../backend/prisma/schema.prisma) models organizations, users, memberships, projects, tasks, and retained audit events.

Trace task creation carefully. The route supplies the project identity from the URL, while verified context supplies the organization. The body supplies only title and status. The repository checks that the parent project belongs to that organization, inserts the task, and inserts audit metadata in one transaction. A composite foreign key also requires the task's organization to match its project's organization. This is a database invariant as well as an application query convention.

On the frontend, [App](../frontend/src/App.tsx) owns the in-memory session and selected membership. [The organization selector](../frontend/src/features/organizations/pages/OrganizationsPage.tsx) displays only memberships returned by the server. [ProjectsPage](../frontend/src/features/projects/pages/ProjectsPage.tsx) owns separate project/task drafts and captured baselines. [The API client](../frontend/src/api/client.ts) sends the token and organization header, parses errors, and supports cancellation and timeouts. React Query keys include user and organization, so cached results from one workspace do not stand in for another's data.

The [seed](../backend/src/seed.ts) supplies fictional accounts and preserves existing demo identities on repeat. [Local setup](../scripts/setup-local.mjs) generates environment credentials without overwriting files. [The verification helper](../scripts/test-database.mjs) owns a temporary database and removes it only after shutdown is confirmed.

As a reading exercise, annotate every transition with its input and output. A user-selected tenant is untrusted input until membership lookup succeeds. A form draft is unsaved intent until a transaction commits. A successful mutation and a later list refresh are separate outcomes. Those labels make the architecture easier to reason about than a diagram containing only framework names.
